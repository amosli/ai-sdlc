## 一页结论（TL;DR）

1. **提效的真相**：任务级提速（55%）≠ 交付级收益；资深开发者在熟悉大代码库上用 AI 实测慢 19% 且自以为快 20%（METR）——一切提效声明必须客观基线复测。AI 是放大器（DORA 2025），放大组织既有的好与坏。
2. **不破坏旧功能的答案 = 四层防线**：智能测试选择（Meta 成本减半/99.9% 故障上报；字节 Bytest 成本 -44.9% 零逃逸）+ LLM 补测试（必须过硬过滤器，TestGen-LLM 73% 进生产）+ 行为锁死（契约/快照/特征测试）+ 变更风险推理（Meta DRS、美团后羿）。
3. **回归有效的地基是 flaky 治理**：Google"1/6 的 flaky 转变是真 bug"、Uber 治理 -85% 后才敢自动重试；有效性度量靠变异分数（覆盖率会撒谎：80.7% 行覆盖只有 61.3% 变异分数）。
4. **每改动测到前后端 = 分层门禁**：结构层（Nx affected/SmartEye 精准测试）→ 契约层（Pact 双边 verify，最便宜的"改一处测两头"）→ E2E 层（Playwright MCP/agentic QA）→ 判定层（失败自动分诊）。
5. **AI 判断逻辑 = AI 提议 + 确定性过滤器 + 人类终审**：MT-Bench 证明 judge 可用（>80% 人类一致率）但有位置/冗长/自偏好三偏差；评审器的第一战场是降噪（Graphite 9:1→1:1 的教训）；批准权永远在人。
6. **深入业务流程的前提是工件化**：spec（SDD）、Gherkin 场景（BDD 复兴：AI 生成场景 95% 有帮助/60% 直接可用）、测试计划、流程模型；AI 只能锚定显式工件，不能锚定"心里的默契"。
7. **需求识别的杠杆在需求端**：先修需求描述再让 AI 干活（REAgent +17.4%）；AI 倾向脑补而不是反问（ClarifyCodeBench）；棕地维护的安全网（特征测试/契约）先行再动 AI；大迁移确定性工具打底、LLM 处理长尾（Meta Kotlinator 是规则+AST 而非 LLM）。
